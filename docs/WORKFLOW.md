# NoteBi 开发工作流

## 唯一事实来源

按下面顺序判断当前事实：

1. 当前代码、运行结果和 `git log`
2. [`AI_HANDOFF.md`](AI_HANDOFF.md) 的当前执行指针
3. [`PRODUCT_DECISIONS.md`](PRODUCT_DECISIONS.md) 的已确认产品边界
4. 用户当前点名的 `plans/*.md`

历史计划、截图和旧验收材料不作为当前决策依据，需要时从 Git 标签和提交恢复。

## 任务流程

1. 启动时只运行 Git 三项检查，确认分支和未提交内容。
2. 调查任务先定义可验证目标，产品取舍由用户确认。
3. 每个执行任务使用独立 `codex/*` 或 `feat/*` 分支。
4. 不在脏工作树上判断单个提交是否通过。
5. 先跑相关测试，再按风险决定是否跑全量测试、构建和浏览器验收。
6. 完成的计划从当前树删除；结论写入交接，历史保留在 Git。
7. 先审核再合入 `main`；不主动 push。

## 当前阶段

- 第一阶段：仓库清理、未完成功能分离、文档收敛。
- 第二阶段：完成批量来源和任务生命周期。
- 第三阶段：功能盘点、短期计划、长期路线图。
- 第四阶段：macOS/Linux 全功能验收。
- 第五阶段：Windows 实机适配与源码可见整合包。

## 红线

- 不删除或迁移用户工作区、媒体、索引、设置和模型数据。
- 不把暂停实现成取消。
- 不恢复 ReplicaBi、分镜、AI 导演或提示词生产功能。
- 不泄露 API key、Cookie、Token 或本地路径中的个人数据。
- 不为通过测试而改变已确认产品语义。
