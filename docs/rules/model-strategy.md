# 执行工具选择策略

> NoteBi 默认由 Codex 完成调查、计划、实现和验证。Claude Code / 千问可选，但绝非必经环节。
>
> Last updated: 2026-08-03

## 1. Codex：默认执行者

以下工作默认由 Codex 自己完成：

- 当前 Git / 运行状态对账、根因调查与调用链追踪；
- 产品选项、风险说明、可执行计划与验收标准；
- 已授权范围内的代码修改、测试、浏览器验证和本地 commit；
- 对自己的 diff、退出码与实际运行结果进行复核。

用户只说“调查、审核、计划、看看怎么解决”时，Codex 保持只读，不自动进入业务实现。

## 2. Claude Code：用户指定时才使用

- 用户在当前任务明确要求 Claude Code / 千问时，Codex 才可调用它处理单一、边界清楚的子任务。
- 外部执行器先红后绿、最小修改、相关验证和 commit 的结果不替代 Codex 最终复验。
- 用户没有明确指定时，Codex 不启动、监控或等待 Claude Code；实现、测试和 commit 由 Codex 直接完成。
- 如需使用，启动前后都必须重新对账 Git；不并行修改同一工作区，不输出 token 或其他密钥。

## 3. 成本不是降低验证的理由

真实代码、Git、退出码和运行结果始终优先于任何工具总结。风险高时，Codex 应按范围运行 build、全量或浏览器回归；若未验证，明确说明边界。

## 4. Open Design 的定位

- Open Design 是 Codex 可调用的设计/评审工具：只在已授权且涉及用户可见 UI 的批次使用。
- 它不写生产代码；Codex 根据确认的设计产物、真实代码与数据契约实现。
- 没有 UI/设计需求时不强制调用。设计产物冲突时停止并向用户求证。
