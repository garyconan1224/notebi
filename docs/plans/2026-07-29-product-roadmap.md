# NoteBi 长期产品路线图

状态：方向已确认，具体阶段在进入前再细化
产品原则：本地优先、证据优先、单产品、功能完成后再跨平台打包

## 1. 产品终局

NoteBi 是本地优先的多媒体笔记工具：

- 导入视频、音频、图片和文本；
- 生成可编辑、可追溯、可导出的统一笔记；
- 保留画面、OCR、字幕、说话人和来源证据；
- 在合集和全局知识库中搜索原文、基于证据问答；
- 本地管理模型、网络、Cookie、任务、数据和日志；
- 最终提供 macOS、Linux、Windows 的稳定启动和可复现安装方案。

不进入路线：

- Nibi / ReplicaBi 多产品模式；
- 复刻、AI 分镜、AI 导演和生成提示词；
- BPM、调性、情绪、音乐风格、音乐教学或 Suno/Udio；
- 云端账号、多用户协作、移动端和云同步，除非未来重新立项确认。

## 2. 阶段门槛

### Gate A：功能闭环

执行短期计划 S0–S5。

退出条件：

- 批量任务、批量导出、任务默认值和编辑器工具栏完成；
- 所有用户可见占位清零；
- 四类笔记主要链路无已知阻断缺口。

Gate A 未通过，不开始 Windows，也不制作正式整合包。

### Gate B：macOS/Linux 质量与真实验收

目标：

- 全量测试、lint、构建、依赖检查通过；
- 真实平台和本地文件矩阵通过；
- 失败、取消、重试、重启恢复可验证；
- 大文件、长音视频、中文路径、空格路径和无网络场景行为清楚；
- 用户数据备份、恢复、软删除和彻底删除边界明确；
- 本地模型首次下载、缓存、切换和错误提示可用。

退出条件：

- 自动检查全绿；
- 关键链路具有结构化 API/浏览器证据；
- 用户确认 macOS/Linux 功能达到可发布水平；
- 不存在必须靠人工修改源码才能启动的步骤。

### Gate C：开源与发布准备

目标：

- 清理许可证、依赖归属、模型许可证和第三方资源；
- 检查仓库历史之外的当前树不含密钥、Cookie、个人数据和运行产物；
- README、安装、故障排查、数据目录和隐私说明与当前程序一致；
- 建立可重复的版本号、变更日志、构建检查和发布清单；
- 明确哪些测试使用夹具，哪些平台输入需要用户自行提供。

退出条件：

- 新机器按照文档可启动；
- 发布检查清单全部有证据；
- 用户批准公开发布或继续仅本地使用。

### Gate D：Windows 实机适配

进入条件：Gate B 已通过。

工作范围：

- Windows 路径、文件名、长路径、编码、权限和临时目录；
- PowerShell/批处理启动、停止、端口占用和进程回收；
- Python、Node、pnpm、ffmpeg、yt-dlp 和浏览器 Cookie；
- CPU、NVIDIA CUDA 和无 GPU 降级；
- Whisper/说话人模型缓存与首次下载；
- 防火墙、代理、杀毒软件和离线环境；
- 四类笔记、批量任务、知识库、导出和数据恢复实机矩阵。

约束：

- 不用 macOS 测试或截图冒充 Windows 证据。
- Windows 修复不能破坏 macOS/Linux，必须回跑跨平台自动测试。
- 平台差异尽量收口在启动、路径和依赖适配层，不复制业务逻辑。

退出条件：

- 至少一台干净 Windows 机器完成安装和主要链路实测；
- 重启后设置、模型和用户数据仍可读；
- 无管理员权限时有清晰行为或明确前置要求；
- Windows 专属问题清单归零或由用户接受。

### Gate E：安装包与离线整合包

进入条件：Gate D 已通过。

产物分层：

1. 源码开发包：面向开发测试，可读、可修改、可更新依赖。
2. 在线安装包：检查系统依赖并按需下载。
3. Windows 源码可见离线整合包：包含经许可可再分发的运行时和依赖，
   不包含用户密钥、Cookie、私人数据或不允许再分发的模型。
4. macOS/Linux 启动与安装产物：在真实需求确认后采用相同可复现原则。

必须具备：

- manifest、版本号、文件校验值和构建脚本；
- 首次启动自检、端口冲突、依赖缺失和空间不足提示；
- 数据目录与程序目录分离，升级不覆盖用户数据；
- 卸载、升级、回滚和离线安装说明；
- 在干净机器上从产物而不是开发工作区验收。

## 3. 持续改进轨道

这些工作伴随 Gate A–C，但不能越过主线门槛制造新功能：

- 性能：长媒体处理时间、并发、内存、索引重建和首屏 bundle。
- 可靠性：任务幂等、持久化恢复、损坏数据隔离和诊断日志。
- 质量：lint、类型、测试警告、依赖升级和安全审计。
- 易用性：错误文案、空状态、键盘操作、无障碍和窄屏。
- 文档：当前行为、故障排查、模型能力和平台限制。

每个改进项都必须有基线、目标指标和验证方法；没有测量证据时不做大重构。

## 4. 路线图治理

- 一次只执行一个短期阶段；阶段完成后测试、提交、审查，再进入下一项。
- 当前 Git、API 和浏览器行为高于历史文档。
- 产品行为、设置 schema、数据迁移、依赖安装或安全边界变化必须停下确认。
- WIP、旧标签和历史提交只用于取证，不作为可直接合并的实现来源。
- 不配置 remote、不 push，除非用户单独授权。
- 每个 Gate 进入前，把本路线图拆成当期可执行计划；不提前写大量实现细节。
