# 知识检索 P0 基线证据

日期：2026-07-25

## 数据边界

- 当前共有 44 个非垃圾桶合集、61 条合集内素材记录。
- 只有收纳箱 1 个合集含可索引分析结果，共 19 条素材。
- 其余合集大多只有素材引用，没有 `results` 或可解析的成功任务结果。
- 因此 1 / 5 / 全部合集的性能对比不能直接使用当前数据完成。
- 基准脚本使用当前真实可索引素材，并把素材轮换放入 44 个临时合集。
- 临时数据和缓存都位于系统临时目录，不修改用户工作区数据。
- embedding、reranker 和 LLM 全部使用确定性离线替身，不访问外部模型。

复现命令：

```bash
./.venv/bin/python scripts/benchmark_retrieval_cache.py
```

当前 workspace 检索对每个合集先调用一次 `retrieve_with_sources`，
汇总后又调用一次 reranker。44 合集查询两次共触发 90 次 reranker，
这不是目标架构可以接受的调用方式。

## P0 决策

选择 **workspace 作为缓存单元**，理由：

1. 构建时间与全局缓存基本相同；
2. 缓存占用没有超过全局缓存，当前样本反而更小；
3. 1、5、44 合集的缓存命中查询都更快；
4. workspace 缓存可在单合集内容变化时局部失效。

P1 必须同时把查询改成：

1. 各 workspace 只做向量候选召回；
2. 合并候选；
3. 整个请求只做一次最终 rerank；
4. 再生成回答与引用。

## 来源定位事实

当前每个素材 JSON 只生成一个 `VideoChunk`。转写段落的
`start/end` 没有进入 chunk 元数据；`time_range` 只读取 JSON
顶层的字符串字段，而现有素材通常没有该字段。

所以当前只能稳定跳到素材结果页，不能稳定跳到某条转写片段。
要实现已确认的“回答引用原文并可跳转”，后续必须新增字段级、
段落级 chunk：

- 转写片段：保留 `segment_id`、`start_ms`、`end_ms`；
- 总结/笔记/标题：保留 `field` 和字段内锚点，无时间时跳到对应内容区；
- 无法解析时间的旧数据：允许素材级跳转，但不得伪造时间点。

这项行为需要在 P1 开始前确认。
