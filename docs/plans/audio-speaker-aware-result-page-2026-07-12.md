# 音频统一笔记页与区分说话人总结执行计划

## 1. 用户已确认的产品边界

本计划只处理音频，不改变视频、图片、文字结果页。

必须保留：

- 音频播放器、真实音频波形、播放控制、速度、音量、循环、画中画。
- 转写字幕、时间码跳转、字幕编辑、字幕翻译、字幕导出。
- 说话人识别、筛选、重命名、识别状态和失败原因。
- 普通总结、区分说话人总结、总结风格模板、多版本总结。
- NoteBi 统一笔记能力：笔记编辑器、自动保存、章节、版本、导出、问 AI 等当前音频可用能力。

必须移除音频页面入口和使用流程：

- 音乐分析。
- 音乐转写。
- 音乐模式。
- 提示词页。
- 人声分离。

“移除”默认指不展示、不进入、不触发这些音频能力；后端旧接口只有在确认没有其它调用后才清理，避免误伤其它音频流程。

## 2. 核心架构决定

1. 音频统一笔记页使用音频结果页作为唯一视觉壳层。
2. 音频 `/note` 与 `/audio_detail` 指向同一套音频结果实现，避免两套页面继续漂移。
3. 视频、图片、文字继续使用各自现有 NoteShell / 结果页，不做全局替换。
4. 顶层信息架构暂定为：`转录`、`总结`、`笔记`；播放器固定在页面上方。
5. “区分说话人”是新建总结中的总结方式，不是新的文件夹：

   ```text
   总结方式：普通总结 | 区分说话人总结
   风格模板：现有 standard / meeting / interview / ...
   ```

6. 说话人重命名后，字幕、统计和当前页面立即更新；自动生成新的总结版本，旧总结保留原说话人名称和内容快照。

## 5. 强制停点与不可自行决定事项

出现以下任一情况，立即停止并问用户：

1. 需要新增依赖、下载模型或修改环境变量。
2. 需要修改数据库 schema、迁移或已有持久化字段语义。
3. 实际代码与本计划、现有 NoteBi 功能或用户确认不一致。
4. 发现提示词/人声分离/音乐能力仍被其它非音频功能使用。
5. 需要跨出音频范围，影响视频、图片、文字结果页。
6. 修改文件数超过当前子阶段已列范围。
7. 任何“为了通过测试”而改变用户可见语义的情况。

询问格式：

> 我在执行 X 时发现实际情况是 A，但计划写的是 B。现在有两个方案：1. … 2. …。这会影响 …。请你选择。

## 6. 验收标准

- 用户可以在新建总结中明确选择“区分说话人总结”。
- 该总结的观点、共识/分歧、决策、行动项都能追溯到说话人和时间码。
- 重命名说话人后，字幕和统计立即更新，并自动产生新总结版本；旧版本不变。
- 音频页面仍具备 NoteBi 原有笔记能力。
- 音乐分析、音乐转写、音乐模式、提示词、人声分离在音频流程中不可见且不触发。
- 波形来自真实音频内容，不能以固定随机波形作为最终结果。
- 失败状态说明原因，设置页能给出处理建议。
- 视频、图片、文字功能回归不受影响。
